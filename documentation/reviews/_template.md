# Review title

- **Review ID:** `<scope>-REVIEW-<number>`
- **Date:** YYYY-MM-DD
- **Scope:** Components, claims, or changes reviewed
- **Code baseline:** Commit hash and relevant dirty/untracked source state
- **Related:** Previous reviews, plan, PR, and evidence links

## Assessment

State the main findings and practical implications. Identify what was executed
independently versus inspected or reported, plus hardware/access limitations.

## Findings

| ID | Priority | Finding | Status | Evidence |
| --- | --- | --- | --- | --- |
| Stable finding ID | P1/P2/P3 | Concrete concern | Open | Code link or reproduction |

For each finding, describe impact, reproduction or reasoning, recommended action,
and the evidence needed for closure. Separate defects from hypotheses and scope
limitations.

## Previous findings

Reference earlier finding IDs and record open, partially addressed, closed, or
superseded status with evidence. Leave the original review intact.

## Validation and remaining questions

Record commands, outcomes, artifact locations, and uncertainties that could change
the assessment. Link the review in the documentation index.
